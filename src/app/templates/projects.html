Tosel Lab Platform

20여년간 영어인증능력 시험제도를 통해 입지를 다진 TOSEL의 신규 학습컨텐츠 플랫폼입니다. 전국 학원들을 대상으로 심사과정을 거쳐 TOSEL Lab 지정교육기관을 선별하고, 선별된 지정교육기관과 해당 기관의 원생들을 대상으로 맞춤식 진단 데이터 공유 및 처방과 컨텐츠 제공을 통하여 해당 지정교육 기관의 원생들의 영어능력 성장을 돕도록 기획되었습니다.

2022년 8월 정식 출시된 서비스로, 개발부터 배포 및 운영까지 참여했습니다.
전국 교육기관과 학생들을 대상으로 제공된 실제 상용 서비스입니다.

서비스 초기 기획부터 개발, 소통 및 런칭까지 모든 프로세스에 주도적인 역할로 참여하였고 기존에 Monolothic한 시험 웹사이트에 모든 기능이 몰려있던 TOSEL 사이트 리뉴얼까지 고려하여 TOSEL Lab Main Web Site 및 4개의 Digital Contents가 포함된 Microservices Architecture 방식의 플랫폼으로 설계하였습니다.  

그럼 지금부터 제가 참여했던 TOSEL Lab Platform의 프로젝트들을 소개해드리겠습니다.

This is TOSEL's new learning content platform, built on 20 years of experience running an English proficiency test. Academies nationwide go through a screening process to become designated TOSEL Lab institutions, and the platform was designed to help their students grow by sharing personalized diagnostic data, prescriptions, and learning content.

It officially launched in August 2022, and I was involved from development through deployment and operations.
It was a real commercial service offered to educational institutions and students nationwide.

I took a leading role in every stage, from initial planning through development, communication, and launch. Considering the renewal of the existing monolithic TOSEL test website, where every feature was concentrated, I designed the platform with a Microservices Architecture made up of the TOSEL Lab main website and four digital contents.

Business Model Refactoring

TOSEL Business Process Model을 Microservices Architecture 기반으로 재설계한 프로젝트입니다.

Remodeling TOSEL's Business Process Model on a Microservices Architecture.

배경

Background

  • 기존 TOSEL 웹사이트는 시험 접수·변경·성적 확인을 제공하는 응시자 중심 서비스 플랫폼.
  • 포스트 코로나 시대에 영어 학습 콘텐츠 사업(TOSEL Lab)을 새로 런칭하며 서비스 확장이 필요.
  • 하지만 기존 사이트에 확장 서비스를 붙이기엔 구조적 문제가 많았음.
  • The existing TOSEL website was a test-taker platform for registration, changes, and score checks.
  • Post-COVID, TOSEL launched a learning content business (TOSEL Lab) and needed to expand its services.
  • But the existing site had too many structural problems to extend.

문제점

Problems

  • 노후화된 코드 — 10년간 유지보수만 진행, 낮은 JDK 버전으로 https 기반 API 호출 불가.
  • 정규화되지 않은 DB — 임시로 덧붙인 구조로 중복·쓰레기 데이터가 쌓여 무결성 미보장.
  • 서비스 혼재 — 타깃 유저가 다른 서비스가 Monolithic 구조에 섞여 사용·관리(Admin/ERP)가 어려움.
  • Outdated code — only maintained for 10 years; an old JDK blocked HTTPS-based API calls.
  • Unnormalized DB — ad-hoc structures piled up duplicate and garbage data, breaking integrity.
  • Mixed services — services for different users were tangled in a monolith, hard to use and manage (Admin/ERP).

해결 및 역할

Solution & Role

  • 기존 시험 사이트 전면 리뉴얼 + 신규 학습 콘텐츠 사이트를 Microservices Architecture로 설계.
  • TOSEL Lab과 같은 기간에 진행하며 모든 기획·리팩토링 계획에 참여.
  • 기존 구조의 한계를 분석하고 효율적인 아키텍처를 설계하는 경험 확보.
  • Fully renewed the test site and designed the new learning sites on a Microservices Architecture.
  • Ran alongside TOSEL Lab; took part in all planning and refactoring decisions.
  • Learned to analyze structural limits and design a more efficient architecture.

Tosel SSO

# Tosel SSO project

  • 서비스 간 학습-평가-분석 사이클을 연결하고 데이터를 공유하기 위한 통합 유저 관리 서비스.
  • SSO에서 JWT 쿠키를 발급해 로그인 여부와 데이터 접근 권한 관리, 타 도메인 연계를 위해 CORS 기반으로 개발.
  • refresh-token — 로그인 상태 유지, 만료 전 주기적으로 갱신.
  • access-token — refresh-token으로 발급, 지정 권한 내 데이터 요청, 연장 불가.
  • 서비스 간 정보를 제공하는 S2S Restful API 구축 담당.
  • 모든 서비스의 공통 회원 정보를 먼저 파악한 뒤 통합 회원 DB를 설계해야 함을 체감.
  • An integrated user management service that links the learn-assess-analyze cycle and shares data across services.
  • SSO issues JWT cookies to manage login and data access; built on CORS to connect with other domains.
  • refresh-token — keeps the login alive, renewed periodically before expiry.
  • access-token — issued via the refresh-token, grants scoped data access, cannot be extended.
  • Built the S2S RESTful APIs that serve information between services.
  • Learned that the integrated member DB must start from the shared member data every service needs.

Tosel Book Mall (SCM)

공급망관리시스템(SCM)과 쇼핑몰 역할을 함께 하는 TOSEL 교재몰입니다.

TOSEL Book Mall, working as both a Supply Chain Management system (SCM) and an online shop.

왜 SCM으로 기획했나

Why SCM

  • 초판/증쇄/개정/재고 상태 등 교재 특성상 현황 관리와 트래킹 필요.
  • 일반회원·지역본부·총판 등 4종 유저별로 기능과 화면이 달라야 함.
  • 총판·지역본부는 주문 규모가 커서 증쇄 여부 판단이 필요.
  • 전화·팩스·이메일·메신저로 제각각이던 주문 방식을 통합할 필요.
  • 엑셀 수기 관리로 금액·재고 불일치가 잦아 자동화 시스템이 절실.
  • Textbooks need tracking of editions, reprints, revisions, and stock status.
  • Four user types (general members, regional offices, distributors, etc.) need different features and views.
  • Distributors and regional offices order in bulk, so reprint decisions are needed.
  • Orders came in by phone, fax, email, and messenger and needed one system.
  • Manual Excel management caused price and stock mismatches; automation was essential.

역할

Role

  • 웹/모바일 대응, 프로젝트 기획·유저 플로우·와이어프레임 설계.
  • 교재 DB 설계, 유저별 권한 관리 시스템, S2S API, 메인·상세 페이지 구축.
  • 기존 사업 구조를 빠르게 파악해 필요한 기능을 정의하고 개발하는 역량 향상.
  • Web and mobile support; project planning, user flows, and wireframes.

연세 사랑모아 : 교내 기부·나눔 플랫폼

Yonsei SarangMoa : Campus Donation & Sharing Platform

연세대학교 구성원이 안 쓰는 물품을 기부하고, 판매 수익금으로 나눔을 실천하는 웹 플랫폼입니다.

A web platform where Yonsei members donate unused items, and sales proceeds fund campus and community causes.

서비스

Service

  • 학생·교직원이 물품을 기부하면 저렴하게 판매하고, 수익금은 교내외 봉사단체 및 프로젝트 지원에 사용.
  • 기부자에게 마일리지를 적립해 이벤트 상품으로 교환.
  • 자원봉사자 모집 및 봉사점수·봉사활동 확인서 발급.
  • Items donated by students and staff are sold at low prices; proceeds support volunteer groups and projects.
  • Donors earn mileage to exchange for event rewards.
  • Recruits volunteers and issues volunteer points and certificates.

주요 구현

Key Features

  • 세션 기반 로그인·회원가입, 재학증명서 이미지 업로드를 통한 가입 인증.
  • 권한 등급별 접근 제어 — 미승인·승인 회원·관리자 3단계 권한을 설계해, 재학증명서 검증 후 관리자 승인을 받은 회원만 구매 가능하고 관리자 메뉴는 관리자 등급에만 노출.
  • 기부 물품 상태 관리 워크플로우 — 신청 → 승인/반려 → 판매 완료 → 삭제로 이어지는 상태 전이를 설계하고, 승인·반려 취소 시 신청 상태로 되돌리는 관리자 검수 프로세스 구현.
  • 공지사항·이벤트·좋은 사례 게시물 CRUD 관리 기능.
  • 카테고리별 상품 조회 및 페이지네이션 JSON API (AJAX 연동).
  • 결제 처리 — 구매 내역 저장 및 판매 완료 상태 변경, 마일리지 잔액 검증 후 차감하는 이벤트 응모.
  • 기부 신청(물품 이미지 업로드), 마이페이지 구매·기부 내역, 봉사활동 확인서 발급 페이지.
  • Session-based login and sign-up, verified with an uploaded enrollment certificate image.
  • Role-based access control — designed three permission levels (pending, approved member, admin); only members verified by enrollment certificate and approved by an admin can purchase, and admin menus are shown to admins only.
  • Donated item status workflow — designed the state flow (requested → approved/rejected → sold → deleted) with an admin review process that can roll approvals or rejections back to requested.
  • CRUD management for notices, events, and good-example posts.
  • JSON API for category-filtered, paginated item listing (used via AJAX).
  • Payment handling — saves purchases and marks items sold; event entry that checks and deducts mileage.
  • Donation form with item image upload, my page with purchase/donation history, and volunteer certificate page.
